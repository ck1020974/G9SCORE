# G9 成績分析

以本機 HTTP 伺服器或原有靜態網站開啟 `index.html`。

## 級別資料

- `data/cohorts.json`：級別清單、預設級別與檔案路徑。
- `data/114.json`：既有 121 筆資料，新增穩定 ID 與明確班級／分組欄位。
- `data/115.json`：已匯入一模141位學生，901班36人，902至904班各35人；分組尚未提供。
- `scores.json`：遷移前原始資料，保留備查；網頁現在讀取各級檔案。

級別（例如114級）與學年度分開記錄。`academicYear` 尚未確認，保持 null。
預設進入115級。115級來源有1筆作文缺漏及3筆五科成績不完整，空白保留，總積分沿用報表；不補推缺少科目的分數。
每份資料包含 `schemaVersion: 1`、`cohort`、`exams`、`display` 與 `students`。
目前支援一模、二模、三模、四模、會考；`exams` 只列已匯入的項目。
所有頁面的資料、搜尋與排名均限於目前級別，切換級別會清除篩選與學生選取。

學生 `id` 必須唯一、固定且後續補考試時沿用，優先採用學號。114級缺少學號，首次遷移指定 `114-0001` 等 ID；不要依姓名或座號重新產生。
保留 `班級`／`組別` 供原有查詢，另外記錄 `九年級班級`、`高一班級`、`九年級組別`、`最終直升`；額外分組沿用 `額外分組`。
114級仍依已確認的顯示設定隱藏1001、1002班與A組比較項目，總覽與最終直升統計保留。未自動將高一班級還原成九年級班級參與比較。

空白／null 表示缺少成績，不作零分。總積分的實際0分會計入統計。舊資料等第「0」視為未提供等第，不計入等第分布。平均附有效總積分人數。

作文統一記錄0至6級分（`essayScale: grade6`），畫面沿用原欄位名稱「寫作積分」。114級會考作文由原積分反向換算：0.1→1、0.2→2、0.4→3、0.6→4、0.8→5、1→6，原積分保存在`作文原始積分`。總積分沿用來源計分，不以六級分取代其中的作文積分。
換算依據：https://12basic.tp.edu.tw/conslt/超額比序/
RN300 報表已同時提供作文級分及作文積分，直接讀取級分並核對對應關係。
`tools/prepare-rn300.py` 可轉換RN300報表，使用實際儲存格位置讀取，支援報表錯誤標示為A1的工作表範圍。輸入級別、考試名稱、來源與輸出路徑，先產生待匯入JSON再由匯入工具檢查。沒有分組欄位時標為「未分組」，不根據班號推測。

## 匯入

收到原始Excel後，先核對欄位、學生ID、班級分組與考試名稱，再轉成上述格式。
準備好的完整級別JSON可先檢查：

```powershell
node tools/import-cohort.cjs 115 待匯入.json
```

確認檢查報告後，加入 `--write` 更新該級資料；保留 `.backup`。
這個工具替換該級完整資料，不會自動合併部分考試；新增考試須先按固定ID合併到完整資料，再檢查與匯入。
網頁沒有上傳按鈕；Excel轉換會在資料提供後依實際格式完成。
